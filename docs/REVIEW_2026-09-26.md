# TRUSTMEBRO project review — 2026-09-26

Reviewed PR #1 from commit `79cc363`, following `AGENTS.md` and the Karpathy guidelines.

## Confirmed problems fixed

- Reset Stake recreated validator keys. Repeated resets accumulated wallets with the same
  institution names and invalidated signature verification for existing PoS blocks.
  Reset now restores demo stake using the existing registry and keys.
- Wallet seeding was duplicated across pages. `init_state` now reconciles by address
  on every rerun, including newly registered validators. User-created wallets are retained.
- Wallet selectors using names could pick the wrong identity. They now use addresses
  or indices with address-qualified labels. The wallet list identifies current validators.
- Signing another message left verification fields stale; those fields now update together.
- Switching credential presets left the previous input values in place; widget state now updates.
- JSON arrays in the claims input crashed the page; invalid claim shapes now show an error.
- Created signed claim transactions had no submission path. Each saved transaction can now
  be submitted to a selected node, retaining its signature and holder proof package.
- Reset Fork called a nonexistent mempool method. It now clears pending transactions,
  replay tracking and queued messages while holding the node's state lock.
- Broadcast recipients shared the same mutable payload. Network delivery now copies each message.
- Local mining could race incoming block processing. Per-node locks serialize core state
  mutations. Mining intentionally holds the lock; this favors simple correctness for the demo.
- Local PoS production could accept a proposer peers would reject. It now verifies the
  proposer and uses the network consensus seed before appending the block.
- Stake attribution accepted matching institution names. Only matching public keys with
  valid transaction signatures receive credential credit.
- App/page titles and project documentation now use TRUSTMEBRO. Repository URLs and the
  existing `create_trustprofile_consortium` Python API retain their identifiers for compatibility.
- Independent exercises are labeled, and unsupported claims of zero electricity usage,
  instant legal finality and hardware benchmark measurements were corrected.

## Validation

- 139 pytest tests pass, including UI regressions and network isolation/concurrency tests.
- Dashboard and all 12 active pages start without AppTest exceptions.
- Tested repeated Stake reset with a pre-existing signed PoS block, signing twice,
  Fork reset, preset changes, invalid claims JSON, and creating/submitting/mining/verifying claims.
- This is automated validation, not a full manual visual or production security audit.

## Remaining scope and priorities

- `get_network` uses a process-wide cached resource. Browser sessions connected to the same
  running server share the simulated network, while wallet lists and holder packages are session state.
- Consensus still uses simplified mixed PoW/PoS scoring. Historical proposer eligibility
  needs stake snapshots to support full historical consensus validation after stake changes.
- Data is held in RAM. A server restart starts a new network; preserve anything needed for
  a report before restarting. Old duplicate wallet entries are not silently deleted.
- The network uses queues within one Python process, not independent machines or sockets.
- Add CI for automatic regression checks and rehearse the full presentation flow with the team.
  Pin/test a common Python and dependency environment before submission.
